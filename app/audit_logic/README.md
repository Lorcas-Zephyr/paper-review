# 逻辑审计智能体（Logic Auditor）

## 简介

从**论证结构、语义一致性与数据库规则**等维度审查论文：对全文或章节做语义建模，按 `main_rules` 等表中的逻辑类规则（如摘要结构、闭环表述等）给出得分与问题项；对外提供传统单请求接口与**一体化审计接口**（从库读论文、合并请求体正文）。

## 在本系统中的位置

- **上游**：调度器默认调用 **8008** 端口：`/audit/paper` 与 `/audit/integrated`（一体化路径在调度器配置中带 `paper_id` 与请求体 `payload.content`）。
- **下游**：PostgreSQL（`papers`、`paper_sections`、`main_rules` 等）。
- **与其它 Agent 关系**：与格式/实验/文献组并行执行，结果一并交给反思服务做冲突与综合。

## 工作流程（一体化接口概要）

1. 根据 `paper_id` 从数据库读取各节正文，拼接为完整内容。
2. 若请求体中 `payload.content` 非空，优先与之对齐（与调度器当前 MD 一致）。
3. 语义建模与规则引擎执行，生成符合协议的审计响应（含细则开关 `enable_rules`）。
4. 结果写入或返回给调度器，供聚合与反思。

## 架构要点

- 规则来自库表 `main_rules`（`agent_code` 如 `LOG`），便于与反思侧 `main_rules` + `rule_judge` 统一指标体系。
- 数据库连接配置在代码或环境中统一维护，须与调度器**同一实例**，避免 `paper_id` 无法关联正文。

## 启动与运行

依赖与入口以本目录 `requirements` 与 `src/logic_auditor/main.py`（或项目约定启动命令）为准。配置数据库与 DeepSeek 等密钥后启动服务，监听 **8008**。

补充说明见同目录 `API.md`、`项目说明文档.md`。
