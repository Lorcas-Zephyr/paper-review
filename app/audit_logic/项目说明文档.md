# DeepLogicAuditorAgent2 项目说明文档

## 项目概述

DeepLogicAuditorAgent2 是一个基于深度学习和语义建模的论文逻辑审计智能体系统。该系统通过自然语言推理（NLI）模型分析论文的逻辑结构，检测矛盾、逻辑跳跃等问题，并根据数据库规则进行综合评估。

## 技术栈

- **后端框架**: FastAPI
- **机器学习框架**: PyTorch + Transformers
- **图结构处理**: NetworkX
- **数据库**: PostgreSQL
- **NLI模型**: cross-encoder/nli-deberta-v3-base

## 主要模块详解

### 1. API服务模块 (src/logic_auditor/)

#### main.py - FastAPI应用入口

**功能**:
- 定义和启动FastAPI应用
- 提供三个主要API端点
- 处理数据库交互和结果存储

**API端点**:

| 端点 | 方法 | 功能描述 |
|------|------|----------|
| `/audit/paper` | POST | 基于语义建模JSON数据审计整篇论文 |
| `/audit/logic` | POST | 审计单个论文切片 |
| `/audit/integrated` | POST | **推荐使用**: 一体化审计接口，从数据库读取论文并完成全流程处理 |

**关键配置**:
```python
DB_CONFIG = {
    "host": "127.0.0.1",
    "port": 5432,
    "database": "postgres",
    "user": "admin",
    "password": "<通过环境变量设置>"
}
```

#### auditor.py - 逻辑审计核心

**类: LogicAuditor**

**核心功能**:
1. **矛盾检测 (Contradiction Detection)**:
   - 数值矛盾检测（正则匹配+阈值比较）
   - 语义矛盾检测（基于NLI模型）

2. **逻辑跳跃检测 (Logic Leap Detection)**:
   - 检查句子间是否存在逻辑衔接词
   - 衔接词库: 因此、所以、因而、从而、导致等

3. **证据追溯 (Evidence Tracing)**:
   - 检查论点是否有前置证据支撑
   - 基于语义相似度判断

4. **循环论证检测 (Circular Reasoning)**:
   - 检测自我证明模式

**主要方法**:
```python
# 审计单个切片
audit_chunk(abstract: str, content: str, context_before: str, chunk_id: str)

# 审计整篇论文
audit_paper(paper_json: Dict[str, Any])
```

#### schemas.py - 数据模型

**Pydantic模型定义**:
- `AuditRequest`: 审计请求
- `AuditResponse`: 审计响应
- `Result`: 审计结果
- `Detail`: 问题详情
- `AgentInfo`: 代理信息
- `Usage`: 资源使用统计

### 2. 语义建模模块 (src/semantic/)

#### semantic_modeling.py

**类: SemanticModeling**

**核心功能**:

1. **命题提取 (Proposition Extraction)**:
   - 分句处理
   - 命题类型分类（core_claim/evidence/sub_claim）
   - 基于关键词的启发式分类

2. **语义关系识别 (Semantic Relation Identification)**:
   - 基于NLI模型的推理（entailment/neutral/contradiction）
   - 基于规则的备选方案
   - 上下文窗口限制（默认20）

3. **语义图构建 (Semantic Graph Building)**:
   - 使用NetworkX构建有向图
   - 节点：命题（含内容、类型、位置）
   - 边：语义关系（含类型、置信度）

**关键方法**:
```python
# 提取命题
extract_propositions(text: str, position: str)

# 识别语义关系
identify_semantic_relations(propositions: List, context_window: int)

# 构建语义图
build_semantic_graph(propositions: List, relations: List)

# NLI模型推理
model_nli_inference(premise: str, hypothesis: str)
```

**NLI模型加载**:
- 首选模型: `cross-encoder/nli-deberta-v3-base`
- 备选模型: `hfl/chinese-roberta-wwm-ext`
- 硬件要求: CUDA GPU

### 3. 论文切片模块 (src/slicer/)

#### paper_slicer.py

**类: PaperSlicer**

**核心功能**:

1. **内容提取**:
   - 从Markdown格式论文中提取摘要和正文
   - 排除目录、参考文献等非内容部分

2. **内容清理**:
   - 移除图片、表格、公式
   - 清理多余空白字符

3. **切片处理**:
   - 句子分割
   - 按最大长度切分（默认200字符）
   - 生成语义建模所需的输入格式

4. **命题类型识别**:
   - 基于关键词识别命题类型
   - 核心声明关键词: 提出、认为、表明、证明等
   - 证据关键词: 数据显示、实验表明、根据等

**主要方法**:
```python
# 处理本地文件
generate_semantic_modeling_input(paper_path: str)

# 处理字符串内容
generate_semantic_modeling_input_from_content(content: str)

# 从数据库读取论文
read_paper_from_db(paper_id: str, db_connector)
```

### 4. 数据库连接模块

#### database_connector.py

**类: DatabaseConnector**

**功能**:
- PostgreSQL数据库连接管理
- 论文数据查询
- 章节内容获取

**主要方法**:
```python
# 获取单篇论文
get_paper_by_id(paper_id: str)

# 获取所有论文
get_all_papers()
```

**数据库表结构**:
- `papers`: 论文基本信息
- `paper_sections`: 论文章节内容
- `agent_audits`: 审计结果存储
- `agent_audit_result`: 详细审计结果
- `main_rules`: 审计规则

## API调用指南

### 一体化审计接口（推荐）

**接口**: `POST /audit/integrated`

**功能**: 从数据库读取论文，完成全流程审计

**请求参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `paper_id` | string | 是 | 论文ID（UUID格式） |

**请求示例**:
```bash
curl -X POST "http://localhost:8000/audit/integrated?paper_id=c757eff2-76cd-4833-bc5d-51f2a162c4a0"
```

**响应格式**:
```json
{
  "agent_code": "LOG",
  "audit_results": [
    {
      "result_id": "xxx",
      "paper_id": "xxx",
      "point": "摘要五段式结构完整",
      "rule_id": "LOG-001",
      "score": 5,
      "level": "Low",
      "description": "符合规范",
      "evidence_quote": "...",
      "location": {"section": "abstract", "line_start": 1},
      "suggestion": "..."
    }
  ]
}
```

### 审计规则说明

系统支持以下审计规则（从数据库main_rules表获取）:

| 规则ID | 规则名称 | 满分 | 说明 |
|--------|----------|------|------|
| LOG-001 | 摘要五段式结构完整 | 5 | 检查摘要是否包含背景、方法、实验、结果、结论 |
| LOG-002 | 三级逻辑闭环 | 6 | 检查是否包含宏观理论、中观方法、微观实践 |
| LOG-004 | 术语一致性 | 4 | 检查术语在各章节中的使用一致性 |
| LOG-005 | 相关技术章节闭环衔接 | 3 | 检查相关技术章节的占比和衔接 |
| LOG-006 | 实验回应研究问题 | 3 | 检查实验是否有效回应研究问题 |
| LOG-007 | 创新点数量达标 | 4 | 检查结论中的创新点数量 |

### 完整使用示例

以下是一个完整的Python脚本，演示如何使用系统：

```python
import requests
import time

def audit_paper(paper_id):
    """审计单篇论文"""
    print(f"开始审计论文: {paper_id}")
    start_time = time.time()

    # 调用一体化审计接口
    api_url = "http://localhost:8000/audit/integrated"
    try:
        response = requests.post(
            api_url,
            params={"paper_id": paper_id},
            timeout=300  # 5分钟超时
        )

        if response.status_code == 200:
            result = response.json()
            elapsed = time.time() - start_time
            print(f"审计完成！耗时: {elapsed:.2f}秒")
            print(f"审计规则数量: {len(result.get('audit_results', []))}")

            # 打印审计结果摘要
            for audit_item in result.get('audit_results', []):
                print(f"  - {audit_item['point']}: 得分 {audit_item['score']}, 级别 {audit_item['level']}")

            return result
        else:
            print(f"请求失败: {response.status_code}")
            print(f"错误信息: {response.text}")
            return None

    except Exception as e:
        print(f"发生错误: {e}")
        return None

if __name__ == "__main__":
    # 示例：审计一篇论文
    PAPER_ID = "c757eff2-76cd-4833-bc5d-51f2a162c4a0"
    audit_result = audit_paper(PAPER_ID)
```

## 工作流程

### 一体化审计流程

```
1. 接收请求
   ↓
2. 从数据库读取论文内容
   ↓
3. 论文切片和命题提取
   ↓
4. 语义关系识别（NLI模型）
   ↓
5. 构建语义关系图
   ↓
6. 从数据库获取审计规则
   ↓
7. 执行各项规则检查
   ↓
8. 生成审计结果
   ↓
9. 保存结果到数据库
   ↓
10. 返回响应
```

## 常见问题

### Q: 如何修改切片长度？

A: 在初始化 `PaperSlicer` 时传入 `max_slice_length` 参数:
```python
slicer = PaperSlicer(max_slice_length=300)
```

### Q: 没有GPU可以运行吗？

A: 可以！系统已支持在没有CUDA GPU的环境下使用CPU运行。系统会自动检测CUDA是否可用：
- 如果有CUDA GPU，使用GPU加速
- 如果没有CUDA GPU，自动切换到CPU模式
- 注意：使用CPU模式处理速度会较慢，建议仅在测试或开发环境中使用

### Q: 如何添加新的审计规则？

A:
1. 在数据库 `main_rules` 表中插入新规则
2. 在 `src/logic_auditor/main.py` 的 `rule_check_map` 中添加对应的检查函数

## 注意事项

1. **硬件要求**:
   - 推荐使用CUDA GPU以获得更好的性能
   - 也支持CPU模式，但处理速度较慢
2. **网络连接**: 首次运行需要从HuggingFace下载模型
3. **数据库**: 确保PostgreSQL数据库可访问且包含所需表结构
4. **性能**: 处理长论文可能需要较长时间，建议异步调用
5. **模型缓存**: 模型会缓存到 `model_cache` 目录，首次下载后后续运行会更快
