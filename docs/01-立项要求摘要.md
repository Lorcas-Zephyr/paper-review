# 立项要求摘要

本文依据 `materials/proposal/立项.docx` 与 `materials/proposal/软件工程硕士研究生学位论文质量评价指标.docx` 整理。原文件是唯一立项依据，本页用于工程执行与结题核对。

## 1. 项目目标

项目拟构建面向软件工程硕士论文的智能评价系统，结合大语言模型的语义理解能力与评价策略优化能力，解决人工评阅的主观性、不一致和低效率问题。系统不仅给出评分，还必须返回可定位的原文证据、置信信息和可执行修改建议，最终形成“AI 初筛 + 专家复核”的人机协同流程。

核心研究问题包括：

1. 将选题价值、逻辑严谨性、创新性、实验有效性等主观标准转为可计算指标。
2. 联合分析正文、图表、公式、代码和实验数据等多模态内容。
3. 用 RAG、结构化提示和评价策略优化约束大模型，减少泛泛评语与黑箱判断。
4. 建立可解释、可追溯的证据链，并处理算法偏见、公平性和隐私风险。
5. 通过与专家意见和基线方法对比，验证系统有效性。

## 2. 立项阶段与交付物

### 第一阶段：数据基础与理论准备

- 完成论文智能评价、大模型应用与软件工程教育标准的文献综述。
- 收集并清洗 1000 份软件工程硕士论文及对应评阅意见。
- 建设 MySQL/PostgreSQL 数据库，提取文本、代码、图表和实验信息。
- 形成不少于 300 份高质量标注样本、标注规范和半自动标注流程。
- 标注一致性要求：Cohen's/Fleiss' Kappa 不低于 0.85。

### 第二阶段：模型与核心算法

- 形成系统详细设计、模块接口和架构图。
- 集成文档加载、向量存储、RAG、评价 Prompt 和大模型调用。
- 实现“评阅标准嵌入 + 专家意见迁移/评价策略优化”。
- 交付可上传单篇论文并输出结构化评语的核心原型和 Prompt 模板库。

### 第三阶段：集成与实验验证

- 形成完整 Web 原型，打通上传、解析、评阅和报告链路。
- 完成 1000 份数据标注，并按 7:2:1 划分训练、验证和测试集。
- 与 SVM + TF-IDF、纯大模型调用等基线方法对比。
- 验证语义相似度、维度准确率、生成效率等指标；立项示例目标为语义相似度不低于 85%。
- 系统端到端处理时间目标不高于 5 分钟。

### 第四阶段：总结与答辩

- 提交项目研究论文或结题报告。
- 提交系统最终版及需求、设计、测试、部署、用户手册等技术文档。
- 提交完整实验数据、结果、可复现代码、答辩报告和展示材料。

## 3. 论文评价维度

评价指标文件要求系统覆盖十二类内容：宏观结构与工作量、摘要五段式、绪论与文献质量、相关技术衔接、核心章节理论深度与新颖性、软件架构设计、实验验证、内容逻辑一致性、结论与展望、学术规范与书写质量、研究构件可用性，以及百分制综合等级。

必须重点保留的硬指标包括：

- 核心研究章节占全文 60% 以上。
- 参考文献不少于 60 篇，近三年占比不低于 70%。
- 新方法与近两年至少 3 种主流方法对比。
- 实验与近三年至少 3 种基线在同数据集、同维度下公平比较。
- 图、表、公式均有正文引用和解释；术语、标题与段落三级逻辑一致。
- 软件系统架构覆盖需求，使用 UML 或等价多视图说明，并足以支持第三方复现。
- 构件满足 Available、Functional、Reusable 三项开放科学要求。

## 4. 结题判断原则

“有演示页面”不等于完成结题。最低闭环是：授权数据与标注规范可查、系统可运行、算法方案可对比、实验数字可复算、评语证据可追溯、技术文档可复现、答辩材料与立项承诺逐项对应。
